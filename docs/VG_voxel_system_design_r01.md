# 복셀 시스템 구축 설계서
VG 프로젝트  |  2026년 10월 19일 23시 29분 KST 기준
승인된 이미지에서 형상과 색을 측정하고 실제 3D 복셀 자산을 재현하는 제작 시스템을 구축한다. 이미지 생성은 디자인과 정밀 보정을, 프로그램은 좌표 정합·부피 복원·색 보존·메시 생성·검증을 담당한다. 최종 판단은 실제 엔진의 렌더 결과로 한다.

## 핵심 설계 원칙
• 원본 이미지와 복원 데이터의 연결을 추적한다. 눈대중으로 비슷하게 쌓은 결과를 자동 복원으로 표시하지 않는다.
• 정면·후면·좌·우·위·아래 6면을 필수 검토한다. 사선과 플레이 시점도 추가한다.
• 벽돌·기와·판재별 색 차이를 보존한다. 전체를 공통 12색으로 줄이는 방식은 폐기 대상이다.
• 큰 물체는 부품과 청크로 조립한다. 표면 세부 해상도와 내부 부피 해상도를 분리한다.
• 생성 수량, 데이터 테스트, 실제 화면 검증, 최종 미술 승인을 별도 관리한다.

## 현재 결론
대표 건물에서 이미지 변경이 복셀 형태와 색에 반영되는 연결은 확인됐다. 기단 복구, 긴 지붕 띠 제거, 일부 기와 판독과 난간 구멍 개선도 실제 화면으로 확인했다. 그러나 대표 건물과 도시 전체의 최종 미술 기준은 아직 통과하지 못했다. 3등신 캐릭터는 새 다면도의 비율·방향 불일치가 해결되지 않았다.

## 범위와 완료 조건
도시 외형 품질과 캐릭터 외형을 우선한다. NPC 행동·경제 시뮬레이션과 Windows 이식은 보류 범위다. Git 반영은 별도로 진행한다. 도시 전체 품질 업그레이드 완료 전에 새 통합 플레이 빌드를 전달하지 않는다.

# 1 이미지에서 자산까지의 제작 공정

## 디자인과 입력 승인
원본 사진·캐릭터 자료를 보존하고 사용 가능한 범위를 기록한다. 이미지 생성기로 복셀 제작 예상도와 다면도를 만든다. 캐릭터는 승인된 옷·피부·얼굴·3등신을 유지한다. 생성 그림은 정확한 도면이나 실제 구현 결과로 간주하지 않는다.

## 격자와 반복 보정
코드가 공통 축척·원점·층높이·등록 표식을 가진 템플릿을 만든다. 재료에 없는 단색 배경을 사용한다. 생성 결과의 잘못된 면 방향, 치수, 부품 관계를 구체적 좌표와 함께 수정 요청한다. 수정 결과를 다시 측정해 개선 여부를 확인한다.

## 정합과 의미 분리
배경·격자·표식·물체를 분리한다. 실제 바닥과 공통 기준점을 맞춘다. 창·기단·난간·지붕·식물 등의 마스크와 관측 신뢰도를 기록한다. 모순된 면은 강제로 평균내지 않고 충돌로 남긴다.

## 복원과 재료
실루엣 교차로 외부 부피 후보를 만들고 오목한 회랑·창·난간은 깊이와 단면으로 보완한다. 관측값과 제작 가정은 구분한다. 각 표면 방향에 맞는 참조 면에서 색을 읽는다. 그림자 색을 재료의 기본색으로 무조건 복사하지 않는다.

## 컴파일과 실제 검토
공통 컴파일러에서 부품을 합성하고 외부면을 추출한다. 엔진의 6면·사선·플레이 화면을 원본과 비교한다. 오류를 원본 데이터나 공통 규칙에 반영하고 다시 렌더링한다. 부품별 임시 수정을 범용 기능으로 과장하지 않는다.
보존 순서: 원본 → 승인 시안 → 격자와 다면도 → 정합·마스크·깊이 → 복셀 → 메시·충돌·LOD → 실제 화면과 검증 결과. 각 단계는 입력 해시와 생성 버전으로 연결한다.

# 2 공통 데이터와 복원 규칙

## 통합 목표 데이터 계약
Asset: ID, 버전, 입력 해시, 단위, 축, 기준점, 크기, 셀 크기.
View: 방향, 이미지, 픽셀 축척, 등록 변환, 마스크, 유효·불확실 영역.
Part: ID, 부모, 의미 종류, 경계, 변환, 접합점, 재료와 소유 영역.
Depth: 관측·추정·제작 가정의 구분, 출처, 허용 범위.
Chunk: 점유, 부품 ID, 재료 ID 또는 RGB.
Validation: 등록, 형태, 색, 연결, 6면 렌더, 기능, 성능, 미술 판정.

## 소유권과 결정성
추가·삭제 연산에는 적용 영역과 소유자를 둔다. 뒤 기와의 절삭이 앞 기와를 삭제하거나 회랑을 파낼 때 측면 지주를 지우지 않아야 한다. 같은 입력·버전·seed는 같은 결과를 만들고 청크 처리 순서가 결과에 영향을 주지 않아야 한다.

## 색과 해상도
전체 공통 소수 팔레트 대신 부위별 오차 제한 팔레트 또는 셀별 RGB를 사용한다. 벽돌·판재·기와 ID별 색 변주를 안정적으로 유지한다. 표면만 더 촘촘하게 만들 수 있지만 얇은 외피로 잘못된 깊이나 막힌 구멍을 가리지는 않는다.

## 관측 불가능한 형상
여러 실루엣만으로 회랑 내부·옷의 겹침·가려진 바닥을 유일하게 복원할 수 없다. 추가 단면이나 깊이 정보가 필요하다. 미관측 부분은 설계 가정으로 표시하고 실제 측정이라고 주장하지 않는다. 낮은 신뢰도의 한 면 때문에 다른 면에서 확실한 부품을 통째로 지우지 않는다.

## 표면 방향과 법선
정면 색을 깊이 방향으로 무제한 늘리지 않는다. 지붕 상면은 TOP, 벽면은 해당 입면의 관측을 우선한다. 기와의 미세계단 조명이 잔격자를 만들면 점유·색·경계를 유지하면서 의도된 곡면 법선을 비교한다. 모든 모서리를 일괄 부드럽게 만들지 않는다.

# 3 런타임과 실제 코드 연결

## 구현된 공통 코어
voxel_character/common/core.py: master.v1의 components·parts·instances·paint/cut·assembly_cuts·constraints를 compiled.v1 희소 셀로 변환한다. 셀은 좌표와 instance·part·material·feature 정보를 가진다.
coordinate_planes.py: 공통 좌표. prepared_sampling_v3.py와 exact_sampling_v2.py: 원형상을 유지한 범위 평가.
tools/mesh.py와 common/render_data.py: 재질별 quad, 월드 좌표, rigid_parts를 포함한 riverstone.voxel.render.v1 출력.

## 실제 런타임과 한계
world_city/concept_city_v3/playable_detail_r01의 RenderData.gd, CityWorld 계열, RoadSurfaceSource.gd, SurfacePatchMesh.gd, PlayCity.gd에 상세/원거리 캐시와 이동 중 구역 로딩이 있다. 현재 대표 A 복원 실험은 아직 도시 배치로 승격되지 않았다.

## LOD와 메모리
고품질 원본에서 해상도별 파생물을 만든다. 원본 해시·생성 버전·해상도·재료 설정을 캐시 키로 사용한다. 실시간 생성과 캐시를 병행하고 전체 자산을 한 번에 계산하지 않는다. 대형 JSON은 청크 및 스트리밍 저장을 사용한다. 해상도가 바뀌어도 작은 창·얼굴·통로의 의미가 유지되는지 검사한다.

## 애니메이션과 충돌
common/animation/TransformTracks.gd와 cell_animation, lily_city/runtime에 기존 부위·피벗 기반 걷기·대기와 조작 실험이 있다. 새 승인 3등신 자산의 자동 리깅과 의복 충돌 해결은 완료되지 않았다. GPU 애니메이션과 광범위한 복셀 물리 통합도 확장 목표다.
기존 도시의 493 경로 재생과 도개교·수레·capsule 검사는 별도 증거다. 모든 집 문이나 실내가 검증됐다는 뜻이 아니다. 시각 메시와 충돌은 분리하되 실제 문·계단·난간의 위치와 기능을 대조한다.

# 4 검증 체계와 실패 사례

## 필수 통과 항목
입력: 6면 방향, 바닥·처마·용마루 높이, 등록점, 배경 분리, 캐릭터 3등신·의상·피부.
데이터: 입력 수정의 출력 반영, 외부면 누락·중복·내부막, 색 보존, 부품 절삭 소유권, 청크 순서 독립성.
화면: 같은 카메라의 6면과 사선, 플레이 거리, 창·난간·기단·기와의 판독. 실루엣 일치율만으로 미술 통과를 결정하지 않는다.
성능: 컴파일 시간·최대 메모리·로딩·FPS를 분리한다. 클라우드 소프트웨어 렌더를 사용자 GPU 성능으로 일반화하지 않는다.

## 기단과 지붕
밝은 회색 돌의 배경 오분류와 LEFT 바닥의 12~13픽셀 어긋남이 하단 0.375m를 제거했다. 석재 구분·바닥 정렬로 실제 기단을 복구했다. 계단 단수와 숨은 깊이는 미검증이다. 지붕은 정면 압출로 긴 띠가 생겼고 TOP 기반 타일 대응으로 개선했다. 접합 틈·색 출처·타일 절삭 순서도 수정 대상으로 분리했다. 최종 미술 판정은 아직 실패다.

## 회랑과 색
회랑의 깊이 삭제가 측면 지주·데크까지 제거했고 굵은 기존 표면이 난간 구멍을 막았다. 한 패널의 두 마름모 구멍에 해당하는 43개 주석 픽셀과 뒤 벽 보존을 검사하고 실제 마름모 구멍을 확인했다. 전체 회랑은 미완료다. 4×4픽셀 평균과 공통 12색 축소는 파란 유리를 소실시켰다. 이를 제거한 원본 RGB 창 후보는 현재 실제 렌더 검토 전이다.

## 캐릭터
기존 복원은 머리 아래와 부케가 끊겼다. 새 격자·단색 배경 다면도도 방향 오류와 3.4~3.85등신 변형이 발생했고 국소 수정이 통과하지 못했다. 승인 원본은 유효하게 보존했다. 현재 추가 캐릭터 생성·컴파일은 없으며, 새 완성 결과로 보고하지 않는다.

# 5 실행 계획과 배포 기준

## 첫째 대표 건물 하나 완주
원본 색·얇은 표면 해상도의 실제 전후를 확인한다. 회랑 지지·데크와 남은 지붕 오류를 해결한다. 여섯 면과 사선에서 승인된 시안의 재료·형태가 살아 있는지 검증한다. 대표 A 전용 스크립트와 공통 코어의 책임을 분리한다.

## 둘째 캐릭터 한 개 완주
승인된 보라색 캐릭터 하나의 3등신·방향 정합을 먼저 해결한다. 얼굴·피부·옷·손·부케와 본 부착 정보를 보존한 실제 복원을 검증한다. 건물의 부분 성공을 캐릭터 자동 제작 성공으로 일반화하지 않는다.

## 셋째 다른 자산으로 일반화
다른 집과 분수 등 형태가 다른 자산에 같은 공정을 적용한다. 전용 좌표를 공통 코드에 숨기지 않는다. 입력 변화 회귀와 실제 6면 검토가 새 자산에서도 성립해야 범용 파이프라인으로 평가한다.

## 넷째 도시 전체 적용
검증된 부품·재료·LOD 규칙을 지구별 양식과 대지·도로·출입 방향에 맞게 확장한다. 전체 자산 적용률과 실제 화면 검증률을 따로 관리한다. 현재 도시 전체 미술 통과는 미완료이며 통합 빌드 전달 조건도 충족하지 않았다.

## 저장소와 재현
권장 역할 구분은 specs의 계약, core의 공통 처리, importers의 이미지 측정, assets의 공개 제작 데이터, experiments의 실패·부분 성공 재현, runtime의 엔진 연결, tests의 회귀, docs의 제작 절차와 상태다. 이는 정리 목표이며 현재 모두 이 이름으로 구성됐다는 뜻은 아니다.
VG에는 공개 가능한 소스·설계 데이터·문서를 반영한다. 개인 사진·대화·인증정보는 제외한다. 캐시를 제외할 때 원본·생성기 버전·재현 명령과 미포함 의존성을 명시한다. 초기 README와 작업 브랜치 생성은 확인됐으나 전체 소스 업로드 완료는 아직 확인되지 않았다.
다음 문서 갱신 기준은 대표 자산의 실제 미술 통과, 공통 API로 승격된 항목, 캐릭터 정합 해결 여부다. 파일 수나 테스트 개수 증가만으로 완료 상태를 바꾸지 않는다.
